# Filer

作業ディレクトリのファイルツリーを表示し、git の状態を重ねて見せる。

## 責務

- **ツリーが写すのは選択中の 1 ディレクトリだけ**。ファイル監視は全 worktree に張るが
  （[architecture.md](architecture.md#ファイル監視)）、ツリーは発火源が現在の dir と一致する通知に
  だけ反応する
- **git の状態（status / worktree）は filer が所有しない**。worktree 側が持つものを購読する

## 更新の反映

| 通知              | ツリーの挙動                                                                   |
| ----------------- | ------------------------------------------------------------------------------ |
| ファイル変更      | ルート直下の変更はルートを、サブディレクトリ配下の変更は該当ノードを再読込する |
| git status の変化 | status の再取得 + ツリー全体の再構築                                           |
| 監視登録の再同期  | 消費しない（サイドバーとグラフ側の関心）                                       |

> [!NOTE]
> 作業ツリー由来の status 通知は dir ごとに畳んで遅延発火する（ブランチ切替のような大量の変更を
> 最新 1 回に集約するため）。参照系の通知は畳まず即時発火するため、**ブランチ表示の反映が作業ツリーの
> 書き換え量に従属しない**。詳細は [git.md](git.md)。

## 並走する取得の順序保証

複数の取得が並走しても、**古い応答が新しい応答を踏み潰さない**。

- dir が A → B → A と切り替わっても、同じ dir 値の旧要求と新要求を別物として扱う
- 同一 dir 内で通知が連続しても、先に投げた取得の結果が後の結果を上書きしない
- **応答を反映してよいのは「その要求より後に、より新しい要求が発生していない」ときだけ**

監視対象の登録・解除も並走させない。対象集合の更新が重なっても、**削除済み worktree の監視が
残らない**。

## ツリーの自動展開（reveal）

対象パスまでツリーを展開してスクロールする。

- **reveal 要求の SSOT は「対象の相対パス + 連番」**。各ノードはこれを購読し、自身が対象の祖先か
  判定して展開する
- **同じパスを再度 reveal できるよう、要求ごとに新しい要求として立てる**。購読側は子の読み込みを
  待った後でも、**自分が処理している要求が最新かを判定できる**
- 要求元は 2 経路で、**選択を伴う reveal** と **選択を動かさない reveal** を別の状態として持つ。
  後者を選択経由にすると preview がディレクトリ表示に落ちる

dir 切替と reveal 要求が同じタイミングで起きた場合の順序（dir 変化 → ルート初期化 → 子のマウント後に
reveal）は、**dir の観測を同期的に確定させることで構造的に成立させる**。

## git status の色分け

status のコードから変更種別を判定する。**作業ツリー側を優先し、無ければ index 側を使う**。

| 種別      | 色     |
| --------- | ------ |
| modified  | yellow |
| added     | green  |
| deleted   | red    |
| untracked | green  |
| renamed   | blue   |

**ディレクトリの色は配下の変更種別から推論する**。全て同一種別ならその色、混在なら modified。

## 除外エントリ

`.git` という名前のエントリは、ファイル / ディレクトリを問わず **完全一致で常に隠す**。

- 通常の repo の `.git` ディレクトリと、worktree / submodule の `.git` ファイルが同じ判定で消える
- **完全一致なので `.gitignore` / `.gitkeep` / `.gitattributes` は影響を受けない**
- **gitignore 経路とは独立**。gitignore 対象のエントリは除外せず、表示したまま色を落とす
- 作業ツリー / 過去版のどちらのモードでも `.git` は出ない

## symlink の表示

symlink は **「link であること」と「実体としてどう振る舞うか」を分けて持つ**。実体側の種別で
振る舞いを決めるため、ディレクトリへの symlink は葉に潰れず展開できる。

- エントリ自身の種別に加えて **実体の在り処**を併記する。載るのは実体がエントリのパスと食い違う
  ときだけで、該当するのは symlink 自身と「symlink 越しに列挙されたエントリ」の 2 つ。
  **辿れない link（dangling / 循環 / 中間が非ディレクトリ）は実体の情報を持たない**
- **worktree 配下かどうかの判定は実体パス同士で行う**。worktree 自体が symlink 経由のパスでも
  「実体は worktree 配下なのに外部扱い」にならない
- クリック経路は実体に対する経路（file なら preview、directory なら展開）にそのまま乗る。
  **「symlink」という種別が残るのは実体を解決できないケースだけ**

実体の種別でアイコンが決まるため、link が絡むことは 2 軸で示す。

| 表現                     | 対象                   | 意味                    |
| ------------------------ | ---------------------- | ----------------------- |
| アイコン右下の矢印バッジ | link 自身の行          | この行が symlink である |
| 名前の色                 | 実体が別の場所にある行 | 実体が別の場所にある    |

- **色が link ディレクトリの下層まで続くのは、実体向けの右クリック項目が出る集合と揃えるため**
  （色が付いている行では必ず実体へのアクションが出る）。実体の情報を持たない行はバッジと tooltip で
  表す
- **バッジは行の hover / 選択色に追従せず自前の面を持つ**。背景に溶けると矢印が読めない
- **名前の色の優先順位は git change > link > ignored**。link は gitignore 対象であることが多いため
  ignored より上に置く（下に置くと実運用でほぼ発火しない）。git change に色を譲る行でも、link で
  あることはバッジが示し続ける
- **symlink 配下の変更通知は届かない**（ファイル監視がリンクを辿らないため）。リンク先の変更は
  折りたたみ → 再展開で反映される
- **gitignore 判定の対象は常にエントリ自身の実体パス**。ツリー上の（link 越しの）パスを渡すと
  git が拒否してその階層の判定を丸ごと落とし、無音で ignored 表示が消える。symlink 行にリンク先の
  パスを渡すのも誤りで、git の管理対象は link 自身なのでリンク先の ignored を引き継いでしまう。
  **列挙対象自身が worktree 外にある場合は当該 repo の管轄外なので問い合わせを落とす**

### 実体を対象にする右クリック項目

**左クリックは見えているパスで振る舞い、実体を対象にする操作は右クリックの明示操作でだけ起きる**。
symlink は 1 つの実体に複数の名前がある構造で、UI が暗黙に実体へ正規化すると「どの名前で開いたか」が
復元できなくなるため、gesture で対象を分ける。

対象は link 自身の行に限らず、**実体が別の場所にある行すべて**（link 配下のファイルを含む）。

選択とパスのコピーは **排他**で、判定軸は「filer で開けるか」= 実体が worktree 配下か の 1 本だけ。

| 項目                                        | 条件                           | 動作                                           |
| ------------------------------------------- | ------------------------------ | ---------------------------------------------- |
| `Select original file`                      | 実体が worktree 内の file      | worktree 相対で preview に出す                 |
| `Select original folder`                    | 実体が worktree 内の directory | 選択を動かさずツリーだけ実体へ移動する         |
| `Copy original path`                        | 実体が worktree 外             | 実体の絶対パスをコピーする（ツリーは動かない） |
| Open in default app / Copy file / Copy path | 共通項目                       | **link のパスそのものを対象にする**            |

- 動詞 `Select` は filer のクリック操作の再現を指す。file 行のクリックは選択して preview を開き、
  folder 行のクリックは展開なので、種別ごとの意味差は filer に既にある
- `original` は「link を経由しない元の場所」。link 経由の行はバッジと色が「実体は別の場所にある」
  ことを示しているため、行という文脈の中で一意に読める
- **`Select original folder` は選択を動かさない**。ここを選択経由にすると preview がディレクトリ
  表示に落ちる
- **両方を同時に出さない**。「どちらを使うべきか」の判断をユーザーに預けず、実体の在り処で 1 つに
  定まる

## submodule の表示

submodule は「別 repo を指すポインタ」であり、**親 repo のツリーでは展開しない葉**として扱う。
作業ツリー / 過去版のどちらでも同じ契約になる。

**展開させないのは、配下が別 repo の管理下にあり親 repo の status / gitignore では語れないため**。

### 判定

**判定の SSOT は index の gitlink**。

- 作業ツリー上の submodule は、未初期化なら中身の無いディレクトリ、初期化済みでも `.git` は除外
  対象なので、**ディスク側に初期化状態に依存しない手がかりが存在しない**
- **`.gitmodules` は「設定」であって実体ではないため判定に使わない**（記述の無い gitlink も、
  実体の無い記述もあり得る）
- **conflict 中は作業ツリーに checkout されている側に揃える**
- **ディスク上の種別が gitlink と食い違う場合は実体側の種別を優先する**。ディスクの種別は常に
  実体が SSOT で、index は「submodule として登録されているか」だけを足す
- **問い合わせの anchor は列挙対象のディレクトリを所有する repo**。worktree 内に独立した repo が
  あればその index を見る（ツリーが写しているディスクの実体としては妥当）
- **列挙が worktree 外を見ている場合は問い合わせを落とす**（当該 repo の index の管轄外）
- **並び順はディレクトリ区画に置く**。展開できない葉だが、ディスク上はディレクトリが占める位置にある
- **列挙の失敗は観察ログに残す**。無音だと「submodule が普通のディレクトリとして出る」形で退行が
  見えない。無音にしてよいのは非 git project の場合だけだが、その判別は完全ではなく本物の障害も
  同じ形で無音になりうる

### 表示と click

- **右端に短縮 hash を出す**。名前に続けると幅の狭いツリーでは truncate に飲まれるため右端に固定する
- **submodule 固有の色軸は足さない**。名前の色は git change > link > ignored の優先順位を既に使い
  切っており、4 つ目を足すと競合する。gitlink の変更は status が submodule のパス自身を報告するので
  **既存の git change 色にそのまま乗る**
- アイコンはテーマが持つ最も近い語彙を借用する。**アイコン名を焼き込まず名前から引くので、テーマが
  割り当てを差し替えても追従する**
- **click は pin している commit の GitHub ページを外部ブラウザで開く**。URL は `.gitmodules` に
  しか無いため、列挙のたびに読まず click 時に引く。解決できないケースは無音の不発にせず通知で示す
- **`.gitmodules` の相対 URL は origin の所有者 / repo を基準に解決する**。git 本体と同じ規則で
  末尾成分を落とす
- **URL 解決は「開いている repo が宣言した submodule」に対してのみ定義される**。判定側の anchor と
  ずれる入れ子 repo 配下の submodule は解決できず通知で終わる。**誤った URL を出す組み合わせは
  構造的に起きない**
- **過去版では同じ revision の `.gitmodules` から URL を引く**。パスと URL の対応は commit 間で
  変わり得るので、作業ツリーの対応を過去に重ねると別 repo を指す誤リンクになる
- **右クリックメニューは出さない**。行が表すのは repo 境界の外にある別 repo への参照で、click も
  外部へ出る動作に倒してある。行の対象が外部である以上、この repo のファイル操作は載せない

## 削除ファイルの表示

status が削除を報告するファイルは、**ディスク上に存在しなくても仮想エントリとしてツリーに出す**。
ディスク上の既存エントリと重複しないものだけを追加する。

展開中のディレクトリ自体が削除された場合、**ディレクトリの不在はエラーではなく「見つからない」
として返る**。追跡下の削除エントリがあれば打ち消し線で表示し、untracked なら空にする。
**トーストは出さない**。permission 等の真の読み取りエラーだけをエラー経路に乗せる。

> [!NOTE]
> 削除で preview 表示中のファイルが消えた場合の自動クローズは preview 側の責務
> （[preview.md](preview.md#開閉)）。filer はツリー表示の更新のみを担う。

## ファイルコピー（OS クリップボード）

選択中のファイルを OS クリップボードに **「ファイル参照」として**書く。テキストのパスコピーとは
別物で、他アプリへファイルそのものを paste できる。

- **クリップボードに載るのはパス（参照）であり内容ではない**。paste 時点の最新内容が渡る遅延評価
- **過去版の表示中はコピーを拒否する**。過去版はディスクに実体が無く、パスを載せると「見ていた
  過去の内容」ではなく最新の内容が paste される誤読を生む。**無音の不発は「コピーしたつもり」+
  旧内容の paste 事故につながる**ので、キーボード経路は警告で拒否を明示し、メニューは項目自体を
  出さない（可視 UI は出さないことが説明になる）。同じ理由で Open in default app も出さない
- **成功時も必ず通知を出す**。クリップボードは視覚的状態を持たないため、ユーザーの認識と実状態を
  一致させるフィードバックが要る

## 過去版モード

グラフでコミットが選択されている間、ツリーは「そのコミット時点の全 tree」を表示する。選択を解除
すれば作業ツリーに戻る。

- **「今どこを見ているか」と「戻る手段」を filer 側だけで完結させる**。ヘッダに状態表示と復帰
  ボタンを持ち、グラフ側を操作せずに戻れる
- ツリーの種別は git のオブジェクト情報から導く（作業ツリーモードは実体 + index の gitlink）
- **モード切替でツリーを再マウントしない**。展開状態とノードの同一性を保ったまま、データだけ
  差し替える
- **切替直後、新しいデータが揃うまで旧モードの表示を維持する**。切替のたびに読み込み表示を挟むと
  「今どこを見ているか」の連続性が壊れる。切替が重なっても古い応答は反映しない
- **同名パスで種別が変わった場合は別ノードとして扱う**（種別の変化 = 展開可能性の変化）。
  深い展開状態は失われるが、これは意図的な分離
- **ファイル変更と status の通知は過去版モード中は無視する**。過去版は固定された tree のため
  fs / status の変化と無関係
- **status の色分けと削除ファイルの仮想エントリは行わない**（過去の commit に作業ツリーの status を
  重ねるのは誤情報）
- **filer 独自の過去版ファイル取得経路は持たない**。クリックで選択が更新され、preview が既存の
  コミットモード経路で内容を取る

### click の種別別契約

| 種別      | 動作                                                                     |
| --------- | ------------------------------------------------------------------------ |
| directory | 展開 / 折りたたみ                                                        |
| file      | 選択（preview へ）                                                       |
| symlink   | 実体を解決できない場合のみこの種別。作業ツリーでは選択、過去版では no-op |
| submodule | 展開も preview もせず、pin している commit の repo ページを開く          |

過去版の symlink が no-op なのは、格納されている内容がリンク先のパス文字列でしかないため。

### 選択の境界挙動

- **過去版に存在しないファイルを選んでいた場合、ハイライトは消えるが選択自体は保持する**。
  preview は「見つからない」表示に倒し、別の commit に切り替えればその commit に存在するパスとして
  再評価される
- **worktree 切替時にグラフの選択を解除する経路を filer 側にも持つ**。グラフが表示されない
  構成（非 git project）でも、前の repo の選択が持ち越されないようにするため

### 変更一覧との併存

- 過去版モード中も変更一覧は作業ツリーの差分として動き続ける。**意味の異なるデータソースを同居
  させているが、ユーザー操作の SSOT はどちらも同じ選択経路を通って preview に流れる**
- どちらの経路で選んでも、preview はグラフの選択状態に応じて同じルールでモードを切り替える

### スコープ外

- 範囲選択の扱い。範囲選択時は新しい側の tree を表示する
- 過去版モード中のディレクトリの色やバッジ（作業ツリーとは別の意味になるため）

## ファイルアイコン

アイコンテーマの定義から「アイコン名 → 画像」の対応を構築する。解決の優先順位:

- ファイル名の完全一致
- 拡張子の一致（複合拡張子は長い方から順に試す）
- 拡張子 → 言語 ID → アイコン名
- 既定アイコン
