# セッション

作業の単位は Claude Code のセッション。**gozd はセッションを管理する記録を持たない**。
どこで動いたか・タイトル・最終更新は Claude Code のセッションログが SSOT で、gozd はそれを
読んで並べるだけ。

gozd が自分で持つのは、端末とセッションの対応（どの端末でどのセッションが動いているか）と、
稼働中の Claude の状態だけ。どちらも hook で受け取る揮発状態で、永続化しない
（[claude-status.md](claude-status.md)）。

## セッションの帰属

セッションは起動した作業ディレクトリ（worktree / 非 git project の root）に属する。

- repo の一覧は、本体とすべての git worktree で動いたセッションをまとめて読む
- 非対話で起動したセッション（SDK / `-p`）は含めない（`/resume` の一覧と同じ基準）
- 作業ディレクトリが消えたセッション（削除済み worktree）はサイドバーに出ない。
  worktree を作り直して再開する導線は別に持つ（revive）

ログの置き場所と読み方は Claude Code の内部仕様なので、公式 SDK の関数に任せ、gozd では
再構成しない。

## タイトル

**タイトルは Claude Code の記録から決める**。ユーザーが付けた名前（`/rename`）→ Claude が
付けた名前の順で使い、どちらも無いセッションはプロンプトの本文で代える。gozd は名前を付けず、
変更する操作も持たない。

端末が開いているセッションは、稼働中の Claude が端末タイトルとして送る値を優先する。
名前の変更や Claude の命名はまず端末タイトルに現れ、ログの読み直しより早いため。
端末タイトルが取れないとき（起動直後の既定文字列しか届いていない）はログのタイトルを使う。
どちらも無ければ `New session`。

## サイドバー

worktree（非 git project は repo の直下）ごとにセッションを並べる。

```text
WORKTREES
  feature-a
    ● ログイン画面の修正          ← 端末が開いている
    ○ API のリトライ追加          ← 端末が開いていない
    Show more
```

- **端末が開いているセッションを上、それ以外を下に並べる**。見出しで区切らない
- それぞれの中は最終更新の新しい順。端末が開いているセッションはまだログに現れていなくても
  （最初のプロンプト前）行になり、その中の先頭に来る
- **端末を閉じたセッションは下の先頭に移る**。ログの最終更新が最も新しいため、閉じても
  見失わない
- 下は直近のものだけを出し、残りは「Show more」の奥に置く。**Show more は一定件数ずつ広げ、
  全件を一度に開かない**（件数に上限が無いため）。広げた後は初期の件数へ畳める
- 行を消す操作は持たない。古いセッションは新しいものに押し下げられて奥へ下がる
- 端末が開いているセッションには Claude の状態バッジが付く

### クリックの分岐

| 端末     | 動作                                                |
| -------- | --------------------------------------------------- |
| 開いてる | その端末にフォーカス                                |
| 無し     | worktree を選択し、レイアウト先頭の新しい端末で再開 |

**再開の可否を事前に判定しない**。再開が失敗したら zsh 初期化が素の起動にフォールバックし、
新しいセッションとして一覧に現れる。

生きた端末があるのに対応するペインを解決できない場合はエラートーストで通知する。
クリックが無反応に終わる経路を作らない。

### 一覧の更新

一覧は repo 単位で読み直す。読み直すのは、repo を追加したとき、選択中の worktree を切り替えた
とき、セッションの開始 / 終了 hook を受けたとき、端末を閉じたとき。**ターンの途中や git の変化
（commit 等）では読み直さない**。gozd の外で起動・終了したセッションは hook が届かないため、
その repo の worktree を選んだ時点で反映される。端末が開いている
間は端末タイトルと Claude の状態が表示を担い、ログの値が要るのは端末が閉じてからのため。

### 行のメニュー

「Show session log」だけを持つ（下記）。

## PR / issue から worktree を作る

PR / issue の一覧から worktree を作れる。作った worktree は GitHub の参照を記録しない。

- **PR 経由**: その PR の head ブランチを**そのまま使う**。git は同じブランチを 2 つの
  worktree に checkout できないため、head ブランチの worktree が既にあれば、選択はそこへの
  切り替えになる
- **issue 経由**: ブランチ名はタイムスタンプ形式（通常の新規作成と同じ）。**同じ issue に
  worktree を何本でも持てる**（別のアプローチを並行して試す用途）

既存の作業の有無は一覧に出さない。作業へ戻る導線はサイドバーのセッション行が担う。

### 連続作成

一覧を閉じずに accept して、複数の PR / issue から連続で作成できる。

**別の対象への accept は並行に走り、ブロックするのは同一対象の実行中の再選択だけ**（連打で
意図しない本数が増えるため。PR ではブランチの二重 checkout になるため作成自体が失敗する）。

**実行中かどうかの判定はダイアログの外に置く**。ダイアログの状態は閉じると消えるため、
そこだけに持たせると開き直して同じ対象を選ぶ経路を素通しする。**実行中の同一対象を再選択しても
worktree は増えない**。進行中の表示は開き直した一覧でも残る。

**再選択したときの見え方は一覧で違う**。issue の一覧は実行中である旨が通知され、PR の一覧は
選択が無反応になる。

同一秒内の並行作成によるブランチ名の衝突は、**タイムスタンプ生成がプロセス内で一意を保証する**ため
起きない。

### PR / issue URL の事前挿入

どちらの経路でも、作成直後の自動起動は **URL をプロンプト入力欄に挿入した状態**で起動する
（挿入のみで送信はしない。ユーザーが指示を書き足してから送る前提）。

URL は永続化しない。作成時の値を起動時の環境変数として渡し、zsh 初期化が消費する。

## エージェントから worktree を作る

端末で動いているエージェント自身が、作業を切り出すために worktree を作れる
（[architecture.md](architecture.md) のソケット受付）。この操作を説明する skill は gozd 自身が
配布し、gozd が起動した Claude にだけ渡る — 使えない場所では見えない。

- **渡した指示は送信され、そのまま実行が始まる**。一覧経由の作成が URL を入力欄に挿入して人の
  送信を待つのと対照的で、切り出す側は相手が動き出すところまでを指示している
- **名前は付けない**。起動したセッションのタイトルは他と同じく Claude が決める
- **選択中の worktree は動かさない**。この経路の起点は人ではなく、人はそのとき別の worktree で
  作業している。切り出しは人の作業の中断ではないため、端末は前面に出さずに起動し、キーボードの
  入力先も移さない。存在はサイドバーへの追加と Claude ビューへの掲載で知らせる。人の操作を起点にする
  作成（一覧経由 / 新規作成ボタン）は作った worktree へ切り替える
- **指示文は claude が起動するまでどこにも残らない**。作成の応答は「main が作れたか」だけを表し、
  指示文の受け渡しは後段の UI 反映が担う。**UI 反映が失敗したら、指示文をコピーできる形で
  通知に出す** — 出さないと何が失われたか分からず、手で渡し直せない。起動した後は Claude の
  セッションが指示文を保持する
- **起点ブランチと命名は通常の新規作成と同じ**（リモートの既定ブランチ起点、タイムスタンプ名）

## セッションログの表示

セッション行のメニューから開く。Claude Code が書き出したセッションログを整形した
トランスクリプトとして表示する。

### ファイルの解決

**cwd からログの置き場所を再構成しない**。エンコード規則は Claude 側の内部仕様で将来変わりうるため、
セッション ID による検索で解決する。**セッション ID は文字種を検証してパストラバーサルを塞ぐ**。

生の JSONL を返す経路と、それを解釈する経路を分ける。**ログ形式の変更に追従する責務は解釈層に
閉じる**。

### 表示するもの / しないもの

**表示する**: 会話イベント（ユーザー / アシスタント / 思考 / ツール / 画像 / 質問）、ユーザーの中断、
エージェントのコンテキストに注入されたシステム由来テキスト。

**表示しない**（件数だけ集計して末尾に出す）:

- 非会話レコード
- ハーネスが内部的に注入したユーザー扱いのレコード。**先頭のラッパータグで判定し、本文中にたまたま
  同じ文字列を含む生の発話を誤認して切り詰めない**
- 平文を持たない思考（暗号化のみ / フィールド欠落）。ただし**会話イベントではあるので別枠で
  集計し、別ラベルで表示する**

**ユーザーの操作は表示する**。スラッシュコマンドの起動と、作業中に積まれたコマンドは、
**上流が分類済みのメタデータを SSOT にして採否を決める**。本文のパターンから種別を再導出しない —
再導出すると正当な生の発話を取りこぼす。

### 表示の契約

- **ツールの呼び出しと結果はペア化して 1 ブロックにまとめる**
- **質問ツールは会話（Q + A）に畳む**。選択肢を chip として並べ、選ばれたものを強調する。
  回答の SSOT は上流が組み立てた構造化データで、**自然言語のテキストからは復元しない**（引用符を
  含む質問で壊れるため）
  - **回答が来ないケースは「未回答」として可視化する**（silent drop にしない）。テキストからの
    フォールバック経路は持たない
  - **空文字の回答も「未充填」に畳み、判定を 1 条件に閉じる**。表示側の分岐が parser の不変条件に
    一意に従うようにするため
  - **parser 側に「どの種別を見せるか」の表示制約を持ち込まない**。展開した結果から何を出すかは
    表示側が絞る
- **システム注入は折りたたみの中央行で表示する**（「エージェントが何を指示されて動いたか」の
  観察可能性）。注入元は名前で識別する。**内容が空のものは表示する中身が無いので出さない**。
  会話ターンではないため現在地の追従の対象にも含めない
- **ユーザーの中断は発言にせず、中断した位置だけを示す**。全文の表示では中央行に出し、本文の抜粋だけを
  並べる面（ターミナルのセッションプレビュー）には出さない。会話ターンではないため、現在地の追従の
  対象にも rewind の分岐候補にも含めない。中断で終わったログは応答中として扱わない
  - 上流が中断に付けるメタデータは一方の文言にしか付かず、判別の鍵にならない。**記録の形と固定
    文言の完全一致で判定する**。人間が同じ文字列を打った発話は記録の形が違うので、発言のまま出す
- **発言はどれも同じ形式の吹き出しで描画し、種類の違いは本文冒頭の印でだけ示す**。本文は話者に
  よらず markdown として描画する。印は本文の文字列に含めない（コピーに混ざらず、markdown 構文にも
  干渉しない）。本文が空の発言は表示する中身が無いので出さない
  - 本文中の HTML は要素にせず、書かれた文字のまま出す。発言の本文は会話で書かれた文字で、HTML と
    して解釈すると文字が消えたり別の要素に化けたりする
  - 本文の抜粋だけを並べる面（ターミナルのセッションプレビューの吹き出し）は、話者によらず書式を
    解釈せず平文で出す。本文は全文の表示で読む
  - このセッションのエージェントに指示する側（main では人間、サブエージェントでは親エージェント）の
    発言は右側に出す。他のセッションのエージェントから届いたメッセージも指示する側の発言で、印で
    見分ける。その印には送り手を添える
  - 指示を受けて動くこのセッションのエージェントの発言は左側に出す。思考もエージェントの発言で、印で
    見分ける
  - 質問ツールの質問はエージェントの発言、回答は指示する側の発言として出す。質問の見出しは質問の
    印にする。未回答の表示も回答の側に出す
- **どの種別を誰の発言として出すかの判定は 1 か所に閉じる**。ターミナルのセッションプレビューなど、
  セッションログを表示する面はすべて同じ判定で吹き出しを選ぶ
- **現在地のナビゲーションは横断タイムラインに集約する**。Main の画面上端に見えている会話の時刻を
  playhead で示し、タイムラインのクリックで該当ペインをその時刻へスクロールする

### サブエージェント

サブエージェントの会話は別ファイルに記録される。これも列挙して表示する。

- **Main を左ペインに常時表示し、サブエージェントがあれば選んだ 1 つを右ペインに並べる**。
  選択は横断タイムラインと起動元のツール行から行う。無ければ Main を全幅にしてタイムラインも出さない
- ネストして起動されたサブエージェントは、**表示名や所属の情報を兄弟の進捗情報から結合して補う**
- **スクロールは Main を基準に一方向で同期する**。Main を手でスクロールすると、右ペインはその時刻に
  最も近いイベントへ寄る

**Main からサブエージェントへのジャンプ**は、起動元のツール行にボタンを出す。

紐づけは **厳密な一致だけで引く**。一意に決められないときはリンクを張らず、警告として示す。

- ラベルや種別名は呼び出し側が指定する任意の文字列に過ぎず、同名の起動を繰り返すと衝突する。
  **新規起動の解決には使わない**
- 識別子の意味が「起動 1 回」ではなく「処理サイクル 1 回」の粒度になる経路では、同一サイクル内で
  複数が起動されると値を共有しうる。**この場合は一意に決められないためリンクを張らない**
- **「どのツールが紐づけ対象か」の判定は 1 か所に閉じる**。表示側はツール名を判定し直さない

ジャンプ時は **呼び出し時刻に最も近いイベントへスクロールを同期する**。

### 使用モデルの表示

各ペインのヘッダに、そのエージェントが **実際に使ったモデル**を出す。出典はログ内の実測値で、
出現順にユニークに集める。切り替えで複数が混在した場合は連ねて表示する。

**推論の努力度はログに書き出されないため表示しない**（セッションファイルで自己完結する方針）。

### 生ログを開く

各ペインのヘッダから、そのペインの生ログを preview で開ける。Main とサブエージェントは別ファイルの
ためペイン単位に置く。

**生ログは worktree の外にあるため絶対パスの経路で開き、project 未選択でも成立する**
（[preview.md](preview.md) の entry point）。**ダイアログと preview は同時に見せられないため、
ダイアログを閉じてから開く**。

### ライブ更新

ダイアログを開いている間、ログの親ディレクトリを監視する。**ログは worktree の外にありアプリ全体の
監視には乗らないため、ダイアログが自前で監視の寿命を所有する**（open で開始、close で解除）。

- 変更通知は当該セッションの Main / サブエージェントの分だけ拾う。**連続した通知は畳んで再読込を
  1 回にまとめる**
- **再読込は読み込み表示を出さずに差し替えるだけのサイレント更新**にする。再マウントとスクロール
  リセットを避けるため
- 監視の登録は冪等なので、他の監視と共存しても衝突しない

**ボトム追従**: 更新前にボトム付近にいた場合だけボトムへ追従する。スクロールバック中は追従せず、
最新へ飛ぶボタンを出す。初回は最下部を表示する。

- **markdown は非同期に描画されて高さが後から確定するため、追従要求を保留して描画完了後に再適用する**
- **明示的なジャンプ操作が同時に立った場合はそちらを優先する**

## ダッシュボード

全 repo 横断のセッション一覧。並列作業の「次にどこへ注意を向けるか」を選ぶための面で、
コマンドから中央ダイアログとして開く。

- 母集団は repo プール全体のセッション。アクティブ repo list で絞らない（list で絞ると
  「動いているのに出ない」セッションが生まれる）
- 並びは最終活動の新しい順。最終活動は Claude が稼働中ならその活動時刻、それ以外は
  セッションログの最終更新。サイドバーと違い、端末の有無で分けない。開くたびに使い捨てる
  transient な面では「最近動いた = 注意対象」を上に置くほうが目的に合う
- **状態カラムは全行が glyph を持つ**。live な Claude 状態は色つき、Claude が動いていない
  セッションも空白にせず淡色の glyph を出す（空白は「状態なし」ではなく情報の欠落に見えるため）
- タイトル・repo・ブランチを横断して絞り込める
- 行はキーボード操作とクリックのどちらでも選択・確定できる。確定は該当 worktree を選択し、
  フォーカス / 再開に分岐する。**分岐はサイドバーのセッションクリックと同一の SSOT を共有する**
- 詳細ペインに選択セッションの概要（最初の依頼と最後の応答）を出し、切り替えずに
  文脈を思い出せるようにする
- タイトルが最重要カラムであり、表示幅を優先的に確保する。メタデータのカラムは内容幅に
  応じて縮む
- 一覧の中身はライブ更新されるが、並び順は開いたときに確定し、開いている間に増えた行は
  末尾に足す。既存行が入れ替わると確定操作の対象がずれるため
