# Keybinding

キー入力をコマンドにマッピングする。コマンドシステムそのものは [command.md](command.md) を参照。

## 物理キーで照合する

**論理キー（入力される文字）はキーボードレイアウトに依存するため使わない。物理キーで照合する。**

| 操作                  | 論理キー | 物理キー      | 設定文字列      |
| --------------------- | -------- | ------------- | --------------- |
| D を押す              | `d`      | `KeyD`        | `d`             |
| Shift+2 を押す（US）  | `@`      | `Digit2`      | `2`             |
| Shift+2 を押す（JIS） | （なし） | `Digit2`      | `2`             |
| JIS で @ を押す       | `@`      | `BracketLeft` | `[BracketLeft]` |

## 宣言の場所

**既定のキー割り当てはコマンドの登録情報に書く。キー割り当てだけを列挙した独立したテーブルを
持たない。**

コマンド ID を書く欄が登録の 1 か所だけなので、**ID の改名でキー割り当てとパレットのキー表示が
ずれる状態を作れない**。キー割り当ての寿命はコマンドの登録寿命と一致し、条件付きで登録される
コマンドはキーも同時に出入りする（**未登録コマンドを指すキー割り当てが残らない**）。

**ユーザー設定層は持たない**。宣言元はコマンドの登録情報だけで、外部ファイルから割り当てを足す /
打ち消す経路は無い。

### key の書式

modifier + key を `+` で結合。すべて小文字。

**modifier**: `ctrl`, `shift`, `alt`, `cmd`（`meta`, `opt`, `win` も可）

| 設定の key 名                                             | 物理キー                                             |
| --------------------------------------------------------- | ---------------------------------------------------- |
| `a` - `z`                                                 | `KeyA` - `KeyZ`                                      |
| `0` - `9`                                                 | `Digit0` - `Digit9`                                  |
| `up` / `down` / `left` / `right`                          | `ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight` |
| `enter`, `escape`, `tab`, `space`                         | `Enter`, `Escape`, `Tab`, `Space`                    |
| `f1` - `f12`                                              | `F1` - `F12`                                         |
| `;`, `=`, `-`, `.`, `/`, `` ` ``, `[`, `]`, `\`, `'`, `,` | 対応する物理キー名                                   |

**角括弧記法**: `[BracketLeft]` のように物理キー名を直接指定できる。レイアウト依存のキーに使う。

### when の書式

context key の条件式（省略可）。構文は [command.md](command.md) の「When 条件」。

**キーが発火する実効条件は `when` とコマンドの `precondition` の AND**。よって
**precondition で既に効いている key を `when` に再掲しない**。

**同一キーを複数のコマンドに割り当てるときは、実効条件が同時に真にならないように書く。
優先度の仕組みは持たない。**

## 解決フロー

キー入力の listener は **全ウィンドウの文書に張り、解決系（レジストリと context key）は単一を
共有する**。

Escape だけは内側のウィジェットに先に取らせるため、他のキーと処理フェーズを分ける。

同じキーに複数の宛先が並ぶとき、**何で宛先を決めるかは操作の意味で変わる**。

- **閉じる（Cmd+W / ESC）はフォーカス**: サーフェス内にフォーカスがあればサーフェスを閉じ、
  ターミナルにあれば pane を閉じる。両者は排他。Cmd+W と ESC は同義なので同じコマンドに 2 つの
  キーを割り当てる（**ESC はターミナルには割り当てない** — shell へ届く必要があるため）。
  「最前面が閉じる」ように見えるのはフォーカスが前面に追従する帰結で、規則ではない
  （[workspace.md](workspace.md) のサーフェス節）
- **保存（Cmd+S）はフォーカス**: 「今編集しているものを保存する」意味論なので入力先が対象を決める

**切り離した OS ウィンドウは自前の close を持つため、そこにフォーカスがあるときは他の軸から
除外する。**

### 除外判定

| 条件               | 理由                     |
| ------------------ | ------------------------ |
| 既定動作が抑止済み | 他の listener が処理済み |
| 変換中             | 日本語入力中             |
| キーリピート       | 連打防止                 |

> [!NOTE]
> **「OS の予約キー」をハードコードで除外する仕組みは持たない。** bind されていないキーは照合で
> 不一致となり既定動作の抑止を行わないため、ブラウザ既定（コピー / ペースト等）がそのまま動く。
> bind すれば上書きできる。
>
> 例外はアプリケーションメニューの accelerator に bind されたキーで、これは JS に届く前に処理される
> ため bind できない。**renderer 側のコマンドに割り当てたいキーは、メニューから外すのが唯一の
> 共存手段**。

### ディスパッチ

登録済みコマンドを走査し、打鍵が一致して実効条件が成立したものを実行する。
**handler が「処理した」を返した場合だけ既定動作を抑止し、伝播を止める**。一致が無ければ何もしない。

**優先度で解く仕組みは持たない**。多層のレジストリを持つエディタは重み付けで解くが、**gozd の
割り当ては 1 層で、競合はすべて context key で排他にできる**。

**排他の契約が破れて複数一致した場合は、先頭を実行したうえでエラー通知に流す**。どちらが勝つかは
登録順に依存して再現しないため、黙って握りつぶさない。
