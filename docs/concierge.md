# 窓口

repo をまたいだ作業の振り分け・過去のセッションの検索と再開・worktree の片付けを、Claude との
対話で行うための入口。窓口は gozd の端末の中で動く Claude で、gozd の状態を読み、gozd を操作する。

gozd は振り分けの判定ロジックを持たない。行き先を選ぶのは窓口の Claude で、gozd はそのための
状態と操作を渡すだけ。

## 窓口のディレクトリ

窓口は gozd が管理する専用のディレクトリで、非 git の project として扱う。窓口を開くことは、
その project を選ぶことと同じ。

- ディレクトリは gozd（main）が決め、無ければ作る。ユーザーが登録する repo とは別に扱い、
  repo list には載せず、repo の一覧（`app-state.json`）にも保存しない
- **`Cmd+N` で窓口に新しい Claude を起動する**。窓口へ移り、新しい端末で Claude を起動する。
  窓口を開いている最中に押しても、押すたびに新しい端末で起動する。既存の窓口の端末は閉じない
- サイドバーの窓口の行を選ぶと窓口へ移るだけで、Claude は起動しない
- サイドバーのツールバーの直下に固定で表示する。repo list の切り替えや編集モードで消えない。下に窓口の
  セッションを他の project と同じ並びで出す
- **窓口のセッションは毎回新しく始める**。過去の窓口セッションは、必要なときだけ選んで再開する

## 窓口の指示

窓口の役割の指示は、**gozd の中で窓口のディレクトリから起動した Claude にだけ付ける**。
通常の作業セッションのコンテキストを増やさないため。

- 指示は gozd に同梱し、作業中に書き換えられない場所に置く。窓口のディレクトリの CLAUDE.md には
  置かない（Claude が作業中に書き換えうるため）
- 付けるかの判定は起動したディレクトリそのもので行い、窓口の下のディレクトリは含めない
- 聞き返しには Claude 標準の質問 UI を使う。gozd に会話用の入力画面は作らない

## 窓口に渡す操作

操作は gozd の CLI で渡す。MCP サーバーは設けない。窓口は gozd の端末の中でシェルを使える
Claude であり、操作の対象も同じマシン上の gozd に限られるため。

| 操作             | 内容                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| repo の一覧      | gozd に登録された repo と、その worktree                                              |
| セッションの一覧 | 登録済みの全 repo のセッション。最終更新の新しい順で、gozd の端末で動いているかが付く |
| セッションを開く | 指定したセッションを開き、画面をそのセッションへ切り替える                            |
| worktree の作成  | 指定した repo に worktree を作り、指示を渡して Claude を起動する                      |
| worktree の削除  | 指定した worktree を削除する（下記の条件を満たすときだけ）                            |

- **作業を起動しても画面は切り替えない**。窓口との会話を続けられるようにするため。起動した
  作業を見たいときは「セッションを開く」を使う
- **セッションを開くときは、端末が開いていればその端末の dir、無ければ作業ディレクトリで開く**
  （サイドバーのクリックと同じ）。gozd で開いていない dir のセッションは、開く指示を出さずに
  失敗を返す
- 一覧は機械が読む形（JSON）で返す。読むのは窓口の Claude で、人ではない
- 読めない repo（ディスクから消えた等）は一覧から外し、読めなかったことを一覧と一緒に返す。
  1 つの壊れた登録で一覧全体を失わせず、欠けたことは窓口に伝える
- 一覧の元は、この gozd のウィンドウが持つ repo。永続ファイルは複数のインスタンスで共有される
  ため、別のインスタンスが書いた内容を返さない
- PR がマージ済みかどうかのように gozd の外で決まる状態は、窓口の Claude が自分で調べる。
  gozd は持たない

## worktree の削除の安全

取り消せない操作なので、**安全は窓口の判断に頼らず gozd 側で強制する**。次のどれかに当たる
削除要求は拒否し、理由を返す。

- 変更中のファイルがある（untracked を含む）。submodule を含む
- 稼働中のセッションがある。gozd の端末で Claude が紐付いているもの
- detached HEAD である。そこにしか無いコミットを指すことがあり、worktree を消すと到達不能になる
- lock されている
- repo に登録された worktree でない。main worktree を含む
- 要求元が窓口の端末でない。要求元は、要求を出した端末を開いたディレクトリで判定する

Claude の動いていない端末は削除を妨げない。削除した worktree の端末は、worktree の消滅を検知した
時点で閉じる。

未 push のコミットは削除を妨げない。worktree を消してもブランチは残り、そのコミットは失われない。

**要求元の判定は誤操作の防止であり、偽装は防がない**。要求元は要求に載る端末の ID で決まり、
送り手が自分で書ける。ソケットに書ける主体は元より git を直接実行でき、この判定を迂回する
必要すら無い（[architecture.md](architecture.md) のソケットからの受付）。守っているのは、
通常の作業セッションの Claude が片付けの操作に手を出さないことだけ。
