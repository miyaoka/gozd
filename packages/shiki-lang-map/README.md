# @gozd/shiki-lang-map

ファイル拡張子 / ファイル名 → シンタックスハイライタの言語 ID の対応表。

## なぜこの package があるか

ハイライタは「ファイル拡張子からの言語検出」を提供しない（言語 ID を呼び出し側が指定する API 契約）。
一方アプリはファイルパスから言語を決めたい。**両者の橋渡しをする責務をここに閉じ、手書きの拡張子
テーブルを各 feature が持たないようにする**。

対応表の出典は言語判定の de facto SSOT である Linguist のデータで、ハイライタが実際に bundle して
いる言語だけに絞り込む。

## 公開 API

| 名前                          | 内容                 |
| ----------------------------- | -------------------- |
| `LINGUIST_EXTENSION_LANG_MAP` | 拡張子 → 言語 ID     |
| `LINGUIST_FILENAME_LANG_MAP`  | ファイル名 → 言語 ID |

**両テーブルとも、値がハイライタに存在する言語であることを型レベルで保証する。**

## 対応表の方針

- **多重所属する拡張子は決定論的に 1 つへ倒す**（例: `.m` は複数言語に属する）。
  **これと違う方針が要る利用側は自前の override 層を被せる**
- **内容ベースの曖昧性解消（本文の正規表現判定）は実装しない**。拡張子だけでは決まらないものは
  利用側の override で吸収する
- **生成時に、多重所属の一覧と、不要になった明示エイリアスを診断出力する**。後者は検出したら
  失敗させ、**使われないエントリの蓄積を防ぐ**

> [!NOTE]
> 上流の 2 つのデータソースは独立に管理されているため、エイリアス同士の突合には厳密な保証が無い。
> 有名な言語では慣習的な短いエイリアスが共通している経験則に依存しており、**ずれが出たら利用側の
> override で吸収する**前提。

## ハイライタへの依存の張り方

**同じ依存を 2 つの範囲で参照する。**

- **peer**: 利用側に「同じ major を持ち込むこと」を契約として表明する。生成物の型を利用側が解決する
  のに必要
- **dev（固定バージョン）**: 生成スクリプトが参照する。**生成テーブルの決定性を確保するため固定
  する** — 範囲指定にすると、workspace の他の package が新しいバージョンを持ち込んだ瞬間に生成内容が
  変わり、差分がインストールのタイミングに依存する

**両者の範囲が乖離すると型チェックで検出される**。利用側の major を上げるときは本 package の
両方を同じ major に合わせる。
