# サーバー検出

複数の worktree で開発サーバーが同時に立ち上がる環境で、**どの port をどこが掴んでいるか**を
可視化する。port 競合の調査を支援する。

## 検出方式

**ポーリングで検出する。** macOS にはソケットの LISTEN 開始を通知するイベント API が存在しないため、
ファイル監視のようなイベント駆動の経路は使えない。

- **周期走査 + 差分 push**。変化があった走査でだけ push する
- **開発サーバーを起動したら、ユーザーの操作を挟まずに一覧へ現れる**。port 競合の調査を妨げない
  速さで反映する
- **列挙に失敗した走査は丸ごと skip して前回の結果を維持する**。失敗を「0 件」と誤認すると全バッジが
  一時的に消灯する

> [!NOTE]
> 検出できるのは実質「現在のユーザーが所有するプロセスの LISTEN ソケット」。開発サーバーは基本的に
> ユーザー所有なので、port 競合の調査という主目的には十分。対象は TCP のみ。

## 帰属

各 LISTEN プロセスの **親子関係を遡り、祖先が gozd の端末プロセスなら当該 worktree に帰属させる**。
開発サーバーは端末直下の shell の子孫なので、遡れば必ず端末に到達する。

**cwd ではなくプロセスの親子関係で判定する**ため、サブディレクトリで起動したサーバーも正しく
帰属する。

| 種別       | 条件                                               | 表示                     |
| ---------- | -------------------------------------------------- | ------------------------ |
| `live`     | 生きている端末の子孫                               | worktree バッジ + パネル |
| `orphaned` | 過去に帰属したが端末は消滅（閉じた後も掴んでいる） | パネルのみ               |
| `external` | gozd 外のプロセス                                  | パネルのみ               |

orphaned を検出するため、**一度帰属したプロセスと worktree の対応を記憶する**。端末が消滅して親が
付け替わっても、記憶から最後の帰属先を引ける。

## 配送

「mount で pull、変化で push」の規律に従う（[architecture.md](architecture.md#通信経路)）。

- **pull**: renderer の mount 時に直近の結果を取得する（リロード後の再水和も担う）
- **push**: 差分があった走査でのみ発射する

## UI

- **worktree バッジ**: その worktree で LISTEN 中の port をヘッダに表示する。**live のみ** —
  orphaned はその worktree の現役サーバーではない
- **一覧パネル**: 右ドックのサーフェス。各サーバーを **port 単位の行**に展開して port 昇順で並べる。
  **同一 port が複数行に跨るときは衝突候補として警告色で示す**。行クリックで該当 worktree を
  アクティブにし、live なら端末へフォーカスする（external はクリック不可）。
  **ターミナルを見ながら調べる用途のため背景は覆わない**

## 開閉状態の所有

パネルの開閉は renderer の状態が SSOT として所有する。トグルは renderer 内で完結し、
**開閉をミラーする RPC は持たない**。
