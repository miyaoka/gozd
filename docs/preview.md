# Preview

選択したファイルの内容を表示する。ファイル種別に応じた描画と、git の差分 / 過去版の表示を提供する。

## 責務の分離

markdown 描画・blame / 履歴・変更一覧のまとめ表示は、preview 本体から独立した機能として切り出す。
**preview 本体が持つのはファイルの選択・取得・表示モードの決定だけ**で、描画方式の変更が本体に
漏れないようにする。

## ファイル種別

拡張子から判定する。マッチしないものは code として扱う。

| 種別     | 拡張子                                    | 描画                           |
| -------- | ----------------------------------------- | ------------------------------ |
| image    | png, jpg, jpeg, gif, webp, avif, ico, bmp | 画像として描画                 |
| svg      | svg                                       | 画像描画 / ソース切替          |
| markdown | md                                        | サニタイズした HTML として描画 |
| html     | html, htm                                 | ネイティブ描画 / ソース切替    |
| code     | その他すべて                              | エディタで表示                 |

NUL バイトを含むファイルは拡張子によらず内容ベースの判定で「Binary file」表示に倒す。

**描画とソースの切替トグルは、既定の向きと切替可否を独立に扱う**。HTML だけ既定 OFF（ソース表示）
で、それ以外は既定 ON。HTML は「ソースを読む」用途が主なため向きを反転させる。

## モード切替

git の変更対象には Original / Diff / Current の 3 タブを出す。タブ順序は時系列（過去 → 現在）。

**画像として描画している間は Diff を出さない**。下の 2 つの表で Diff が並ぶ行でもタブ自体が現れず、
Original と Current の切り替えで新旧を見比べる。

### Uncommitted モード（既定）

| 変更種別                 | 利用可能なモード        | 既定     |
| ------------------------ | ----------------------- | -------- |
| 変更なし                 | Current                 | Current  |
| modified, added, renamed | Original, Diff, Current | Current  |
| deleted                  | Original                | Original |
| untracked                | Current                 | Current  |

### コミットモード

変更種別は from / to の解決結果から導出する。

- 単一コミット選択: from = `<hash>^`, to = `<hash>`
- 範囲選択: from = `<older>^`, to = `<newer>`（**クリック順ではなく時系列順に整列**）
- 端点に作業ツリーを含む範囲選択: to は作業ツリーの実体、from は `<older>^`。
  **作業ツリーを表す sentinel は RPC 境界を越えず、ワイヤ上は常に実 hash のみが流れる**

変更一覧と同じ取得経路を使うため、**両者の対象ファイル集合は常に一致する**。

| 変更種別                                    | 利用可能なモード               | 既定     |
| ------------------------------------------- | ------------------------------ | -------- |
| modified（from / to 両方あり + 内容が違う） | Original, Diff, Current        | Diff     |
| 変更なし（from / to 両方あり + 内容が同じ） | Current                        | Current  |
| added（from なし、to あり）                 | Original, Diff, Current        | Current  |
| deleted（from あり、to なし）               | Original                       | Original |
| 両方 not found                              | Current（File not found 表示） | Current  |

「変更なし」判定は、ツリー経由でコミット範囲外のファイルを選んだケースを救済する。変更一覧経由では
差分のあるファイルしか出ないため発生しない。**判定は blob の同一性で行い、renderer 側でテキストを
比較しない**。作業ツリー端を含む範囲選択は比較対象が無いため「変更なし」としない。

### Original タブのラベル

タブラベルは `Original (<hash>)` 形式で、**実際に from として読んでいる参照を可視化する**。

| 選択状態           | 表示        |
| ------------------ | ----------- |
| Uncommitted モード | `HEAD`      |
| 単一コミット       | `<hash7>^`  |
| 範囲選択           | `<older7>^` |

## 開閉

プレビューは右端に配置し、既定は閉じている。

**「ファイル選択 → preview を開く / 閉じる」の意思決定は 1 か所に集約する**。各 entry point は
意図に応じて呼び分け、状態の連鎖で暗黙に発火させない。

### entry point × 意図

意図は「同一パスを再選択したときに閉じるか」で分かれる。**一覧や出力から行を選ぶ操作は同一パスで
トグルし、特定のファイルを名指しで開く要求は表示を維持する**。

| entry point                      | 同一パス再選択時の挙動 |
| -------------------------------- | ---------------------- |
| ファイルツリーの行クリック       | close                  |
| 変更一覧の行クリック             | close                  |
| ターミナル出力のパス shift+click | close                  |
| CLI `gozd <file>`                | 維持（再 open）        |
| ファイル検索から選択             | 維持（再 open）        |
| markdown 内部リンク              | 維持（再 open）        |
| markdown の back / forward       | 維持（再 open）        |
| 生ログを開くボタン               | 維持（再 open）        |
| 設定ファイルを開くボタン         | 維持（再 open）        |
| 変更一覧の「まとめて表示」       | まとめ表示をトグル     |
| まとめ表示の Close ボタン        | close                  |
| `preview.toggle` コマンド        | 開閉反転               |
| ESC キー                         | close                  |
| ヘッダの close ボタン            | close                  |
| worktree 切替                    | close                  |
| 表示中ファイルが消える           | close                  |

**close は「まとめ表示を解除する」不変条件を担う**。ESC / close ボタン / worktree 切替 /
まとめ表示の Close はすべてこの 1 経路に集約され、「まとめ表示が有効なのに preview が閉じている」
整合性破綻は構造的に発生しない。

**選択が成立しない入力は no-op に倒す**（空の preview を作らない契約）。worktree 相対パスは
worktree が未確立だと弾かれるが、**worktree 外の絶対パスは worktree の文脈を必要としないため
project 未選択でも開ける**。

例外として、同一パス再選択時にまとめ表示中なら **まとめ表示だけを解除し、preview は閉じない**。
これは close の不変条件とは別経路で、「まとめ表示を抜けて単一ファイル表示に戻る」意味論を持つ。

### その他の挙動

- worktree 切替では自動で閉じる。切替がファイル選択を伴う場合は続けて再 open されるため、
  最終状態は新しいファイルで表示継続になる
- 外側クリックでは閉じない
- Cmd+W と ESC は同義で「フォーカスがあるサーフェスを閉じる」。フォーカスは前面に追従するため、
  結果として手前から順に閉じる（[workspace.md](workspace.md) のサーフェス節）
- 切り離したウィンドウの保存操作は **フォーカスで宛先が決まる**。パネル内と、切り離した後の
  OS ウィンドウ内で保存先が分かれる。close はネイティブの close も含め同じガード経路に合流する
- **open / 前面化のたびにフォーカスが preview へ移る**。ターミナルのリンク経由で開いてフォーカスが
  残ると、入力先が見えない面のままになるため。close 時は開く前のフォーカス元へ戻す。preview 内部に
  フォーカスがあるとき（編集中等）は奪わない
- **開閉の SSOT は DOM を持たない状態に置き、DOM への反映は view が担う**。既に開いている preview へ
  別の中身を出す要求は「開き直し」として届き、前面化に変換される
- IME 変換中の ESC（変換キャンセル）では閉じない
- **表示中ファイルが削除されたときの自動クローズは、どこにも実体が無いと確定した場合だけ**行う。
  作業ツリーで見つからなくなったら HEAD の在否も確認する
  - git 追跡下の削除ファイルは HEAD に内容が残り Original を閲覧できるため閉じない（削除レビュー
    用途）。変更通知が status の更新より先に届いても、HEAD の在否を直接確かめることで誤クローズしない
  - HEAD 不在も git 実行失敗も同じ「不在」に畳む。**RPC 自体が失敗したときだけ不在を確定できず、
    閉じずに notFound 表示に倒す**
  - 単一ファイルの削除も親ディレクトリごとの削除も同じ経路で拾う
  - 閉じない条件は「まとめ表示中 / 絶対パス / 作業ツリーに実体あり」のいずれか

### ファイル操作メニュー

ヘッダのメニューから Open in default app / Copy file / Copy path を出す。項目とアクションは
ファイルツリー / 変更一覧の右クリックメニューと共通で、**メニューの実体は共有しない**
（メニューの種類ごとに独立させる規律）。意味論は
[filer.md](filer.md#ファイルコピーos-クリップボード) を参照。

Open in default app の契約:

- **対象は常に作業ツリーの実ファイル**。過去版を表示中でも開くのはディスク上の実体。
  **表示用のパスを RPC 入力に流用しない**
- **ローカルファイルを開く意図と外部 URL を開く意図は別の RPC に分ける**。後者は scheme の
  allowlist が `file://` を弾くため
- **実体が無いケースではメニュー自体を描画しない**。押せるが必ず失敗するボタンを作らない
- **相対 → 絶対の解決は基準ディレクトリを持つ renderer の責務**。RPC には常に解決済みの絶対パスが
  渡る契約で、**受け側は解決を再実装しない**（再実装すると契約の SSOT が二重化する）
- ただし受け側は入口で **非絶対パス（空文字を含む）を弾く**。これは解決ではなく、空文字や相対パスが
  カレントディレクトリ基準で silent に絶対化される暗黙 fallback を塞ぐためのガード
- **受け側の存在チェックは契約検証ではない**。描画の条件を抜けた後に実体が消えた場合に備えるもので、
  不在ならエラーで弾き（無言の no-op を避ける）呼び出し側が通知する。アクセス制御の関所ではない

## データ取得

| 取得元       | 用途                                     |
| ------------ | ---------------------------------------- |
| 作業ツリー   | 現在のファイル内容（バイナリ判定を含む） |
| HEAD         | Uncommitted モードの Original / Diff     |
| コミット間   | コミットモードの from / to（一括取得）   |
| ファイル履歴 | ヘッダのコミット日と履歴                 |

- **画像 / SVG は専用経路を持たない**。テキストと同じ読み取り経路で得た内容から表示する。内容は
  テキスト / バイナリを型で区別して運び、表示は取得層の意味論（ライブ再取得 / 切り離し時の固定）を
  そのまま反映する
- **worktree 外の絶対パスは git を呼ばず、ファイル読みだけで完結する**
- **rename されたファイルの Original / Diff は旧パスを解決してから読む**。status のキーは新パスしか
  持たないため、status と同一 snapshot で届く「新パス → 旧パス」の対応を使う。旧パス解決を欠くと
  HEAD 側が notFound になり「全行追加」の差分に倒れる
- **バイナリ判定は main 側が行い、内容の型で表現する**（フラグを持たない）

## リアクティブ更新

### git status の変化（Uncommitted モードのみ）

status が更新されたら再取得する。**タブはリセットしない**。

対象の切替でない再発火（自分の保存で unmodified → modified になった等）で既定モードへ倒すと、
Current で編集保存した瞬間に差分タブへ勝手に切り替わる。**ユーザーが選んだタブを維持し、変化で
現在のタブが成立しなくなったときだけ既定へ倒す**。タブのリセットはファイル選択・コミット選択・
PR 差分の切替時のみ。

### コミット選択の変化

再取得する。

### ファイル内容の変化（Uncommitted モードのみ）

選択中ファイルの親ディレクトリが変更対象なら再取得する。モードと表示トグルの状態は維持する。
コミットモードでは git オブジェクトから取得済みの内容を表示するため、ファイル変更通知は無視する。

worktree 外の絶対パスはディレクトリ監視の対象外で通知が届かないため、**表示している間だけ単一
ファイル監視を張る**。選択が外れたら解除する。

**編集中に届いた変更イベントは捨てずに保留し、編集終了で未保存状態が解けた時点で再取得する** —
捨てると変更破棄後に外部変更前の古い内容へ巻き戻り、そのまま保存で外部変更を上書きしてしまう。

ファイル監視は全 worktree を対象とするため、**通知元 dir が現在の dir と一致するものだけに反応する**
（[architecture.md](architecture.md#ssot-push-の-dir-filter-規律)）。

### 並走する取得の順序保証

取得が並走しても、**後から始めた取得の結果が先の結果に踏み潰されない**。反映するのは、その取得より
後に新しい取得が始まっていないものだけ。

## コードビュー

- エディタで表示・編集する。検索と仮想スクロールはエディタ標準の機能を使う。
  **編集可否の切替でタブ切替時に再マウントされない**
- 言語検出は拡張子 / ファイル名から行い、**gozd 固有の方針を上書きとして持つ**。ハイライタが
  対応しない言語はエディタ組み込みの言語情報へ fallback する
- 折り返しをトグルできる
- 行番号指定のリンクから開いたときは該当行へスクロールし、行全体をハイライトする
- blame は行番号クリック、またはメニュー / コマンドから起動する。**ポップオーバーの anchor は
  起動時の位置に固定するため、スクロールしたら閉じる**
- 末尾改行の直後に描画される空の最終行（git の行数に存在しない）は blame 対象外

## 差分ビュー

- 表示モードは `split`（既定）/ `unified`。**preview のセッション内でだけ保持し永続化しない**
- **差分計算の SSOT は git**。renderer 側で全文の差分を回すと、数万行のファイルでメインスレッドが
  固まる
  - 差分アルゴリズムと改行の扱いは **ユーザーの設定に依存させず固定する**
  - **総行数も算出結果に含めて受け取る**。renderer が独自に数えると git の行数え規約と分かれ、
    表示行数がずれる
  - 連続する変更なし行は「N unchanged lines」バーで省略し、クリックで展開する。**展開時の切り出しも
    git と同じ行数え規約で行う**
  - 失敗は pane 内に表示する（トーストだけだと閉じた後に状態を追えない）
- 入力契約: 比較対象は UTF-8 として解釈可能なテキスト。バイナリは上位で弾く前提。すり抜けた場合は
  「正常終了したが出力が想定外」として観察可能化する
- ハイライトは比較元 / 比較先それぞれのトークンを各行に対応付ける
  - unified: 削除行 → 比較元、追加 / 変更なし行 → 比較先
  - split: 左 → 比較元、右 → 比較先
  - **差分の色分けは背景色のみ**。テキスト色はトークンに委ねる
  - 言語未対応時はフォールバック表示（追加 = 緑、削除 = 赤）
- **行内（文字単位）ハイライトは表示専用の追加レイヤー**。行単位の SSOT は git のままで、
  hunk 構造と矛盾しない
  - 行背景と行内の変更範囲は明度で二層に分ける。沈む側での差別化は暗いパレットでは知覚できない
  - **メインスレッドを塞ぐため所要時間の上限で打ち切り、超過分は行単位表示に degrade する**
    （エラーにしない）
- **unified と split の両方を取得時に展開して保持する**。表示モードの切替で再取得しない
- split では変更ブロック内の削除行と追加行を貪欲にペアリングし、余った片側は反対側を空にして残す
- **全選択の範囲は hunk バーを含まない**。省略行のラベルはクリップボードに乗らない。split では
  フォーカスがある半身 1 つだけに閉じる
  - この制御は **フォーカスが差分本体の中にあるときに限定される**。トグルやヘッダのボタンに
    フォーカスがあるときの全選択はブラウザが文書全体に倒す。これは「全選択を JS で横取りしない」
    「選択禁止指定を範囲制御に使わない」（全選択はその指定を尊重しない）方針からの構造的な帰結
- クリップボードは「1 行 = 1 改行」になる。**行番号はテキストとして DOM に存在せず対象外**
- **split の左右は常に 50/50 に固定する**。コンテンツ量比で割らない。半身単位のスクロール枠を
  持たず、長い行は枠を越えて描画され全体の横スクロールで参照する。折り返しで左右の行数が違っても
  行ごとに高い方へ揃える
- 行番号は **blame が使えるときだけ操作可能な要素として描画する**。左は比較元、右は比較先を指す。
  使えないときはフォーカスも hover 対象にもしない（押せないボタンを作らない契約）

## blame / 行履歴

行番号クリックで開くポップオーバー。Esc / 外クリックでの解除と表示位置の反転はブラウザに委譲する。
**ポップオーバーの機構は共通の抽象に委譲し、この層は blame / 履歴の取得順序だけを所有する**。

open / close / 状態は単一の状態に集約し、**view は購読して描画するだけで操作を持たない**
（親から子の内部メソッドを呼ぶ設計は禁止）。ポップオーバー自体はレイアウトの最上位に 1 度だけ置く。

### 参照の決定ルール

| 経路                                     | 参照                   |
| ---------------------------------------- | ---------------------- |
| Uncommitted モードの Current             | 空文字（= 作業ツリー） |
| Uncommitted モードの Original            | `HEAD`                 |
| コミットモードの Current（実 hash）      | `<newer hash>`         |
| コミットモードの Current（作業ツリー端） | 空文字                 |
| コミットモードの Original（単一選択）    | `<newer>^`             |
| コミットモードの Original（範囲選択）    | `<older>^`             |
| 差分モード（比較元側）                   | Original 側の参照      |
| 差分モード（比較先側）                   | Current 側の参照       |

差分モードでは行が属する側で判定する。片側だけの行は反対側に行番号が無く操作要素も描画されない
ため、**クリックされた側は常に存在する側だけになる**。

### 2 つのステート

- **Blame**: 1 行に絞って commit / author / 相対日付 / 概要を表示する。未コミット行は
  "Not committed yet" に倒す
- **History**: その行を変更してきた commit を新しい順で表示する。クリックでグラフ側の選択に反映
  しつつ閉じる

**History は blame の完了を必ず待つ**。起点となる commit と行番号は blame が返した値に固定する。
呼び出し元の参照を起点にすると、`<older>^` などで「blame した commit を含まない履歴」が返り意味
契約が壊れる。blame の失敗 / cancel 時は履歴も失敗に倒す。未コミット行は履歴が空になるため
History タブを無効化して説明を出す。

### 状態同期と順序保証

- 表示中ファイル / コミット選択 / 表示モードのいずれかが変わると閉じる（文脈が乖離した
  ポップオーバーを残さない）
- **anchor が DOM から外れる経路ではすべて閉じる**。内容の再取得は取得の **前** に閉じ、
  一覧更新で項目そのものが消える場合はその時点で閉じる
- **エディタのスクロールでも閉じる**。anchor はクリック時の位置に固定した要素のため、スクロールすると
  行とずれた位置を指し続ける
- **未保存の編集（タイピング）でも閉じる**。blame は保存済みの作業ツリーに対して走るため、行の増減で
  blame 行と表示行が乖離したポップオーバーを残さない
- **閉じる要求は「文脈が完全一致する場合のみ閉じる」形にする**。他の文脈にぶつけても no-op で安全
- Esc / 外クリックを含む close はすべて 1 経路に集約し、進行中の取得を破棄して状態を初期化する
- 一度閉じてから開き直したとき、閉じる前に始まっていた取得の結果は反映しない
- **履歴は「自分が開いたときの blame」だけを待つ**。単に進行中の blame を待つ形にすると、別の行を
  開いた後も古い blame を待ち続ける

### 受け側の防御

- **参照は「空文字 / `HEAD` / hex hash + 末尾の `^` `~`」のみ許可する**。`-` 始まりや空白は
  オプション注入として拒否する
- **blame は空文字（作業ツリー）を許容するが、履歴は拒否する**。履歴の起点は blame した commit を
  流す契約なので、空文字で HEAD 起点の走査に倒れると意味契約が壊れる
- **blame 対象はサイズを先に測り、上限を超えるなら拒否する**。巨大ファイル全体の走査による
  UI ブロックを防ぐ
- **サイズ取得失敗の silent 通過は「予期された不在」経路のみ許す**。それ以外は throw して観察可能化する
- パスに `:` を含むと行指定の履歴取得は構文が壊れるため拒否する
- **出力の parse は各行を trim してから処理する**。末尾の空白で数値 parse が silent に 0 へ倒れるのを
  防ぐ

### スコープ外

- 非 git project、および絶対パスで開いたファイルは git 管理外として、行番号の操作要素自体を
  描画しない
- 単一行のみ。範囲選択は対象外

## ファイル単位のコミット日と履歴

blame が **行単位**なのに対し、こちらは **ファイル単位**。ヘッダに最終コミット日を常時表示し、
クリックでファイル全体の履歴を開く。commit のクリックでグラフの選択に反映する挙動は行履歴と同じ。

行単位とは別経路で、blame のステップを持たず履歴 1 本の状態だけを管理する。ポップオーバーの機構と
commit 行の見た目は行履歴と共有する。

### 参照の決定ルール

**表示中のタブに追従する**。

| 表示タブ       | 参照                               |
| -------------- | ---------------------------------- |
| Original       | Original 側（`HEAD` / `<older>^`） |
| Current / Diff | Current 側（空文字 / `<newer>`）   |

**ファイル履歴は行履歴と違い空文字を許容する**（空文字 = HEAD 起点 = ファイルの最新コミット起点）。
blame 起点の契約がファイル履歴には無いため。差分タブは単一の参照を持たないため Current 側を代表に
使う。

### 表示の条件とリアクティブ更新

- **git repo かつ選択が worktree 相対かつ参照が解決済み、かつディレクトリでないときだけ表示する**
  （押せない要素を作らない）
- ファイル切替 / タブ・コミット選択の切替で再取得する。並走しても古い応答は反映しない
- **HEAD 追従の参照のときは HEAD が動いたときだけ再取得する**。status の通知は作業ツリーの編集ごとに
  飛ぶため、HEAD が同一なら skip して編集の churn を弾く。ファイルの最新コミットが動くのは HEAD が
  移動したときだけ。固定 hash の参照は起点が不変なので再取得しない
- 閉じる経路は行 blame と同じ

### スコープ外

- rename を跨いだ履歴追跡（行履歴が追従していない先例に合わせる）
- 複数ファイル差分へのコミット日表示。単一ファイルのヘッダのみ

## markdown ビュー

- markdown を HTML に変換して描画する。**HTML はサニタイズして XSS を防ぐ**
- YAML frontmatter はコードブロックとして描画する
- mermaid コードブロックは図として描画する（**描画は共有層が担うため全 markdown 経路で効く**）。
  parse エラーはブロック内にインライン表示する

> [!NOTE]
> mermaid は重量級のため、mermaid ブロックが現れるまで読み込みと初期化を遅延する。

### リンクの遷移先

リンク経路の役割分担は [architecture.md](architecture.md) の「外部リンクの navigation 防壁」と整合する。

| href の形式                                           | 遷移先                                                  |
| ----------------------------------------------------- | ------------------------------------------------------- |
| `http(s)://` / `mailto:`                              | OS の既定ブラウザで開く                                 |
| `#fragment` 単独                                      | 同一文書内のアンカーへスクロール                        |
| `/` 始まり                                            | worktree ルートからの相対パスとして表示対象を切り替える |
| `./` / `../` / 名前のみ                               | 現在の markdown のディレクトリ基準で結合して切り替える  |
| 行番号フラグメント                                    | パス部分で切替、行番号はハイライト / スクロールに反映   |
| その他 scheme（`file:` / `data:` / `javascript:` 等） | 無視（信頼境界外として遷移しない）                      |

例外条件と通知:

- **worktree ルートの外を指すリンクと不正な URL エンコードは通知のみでファイル切替を行わない**
- 行番号でない anchor（見出しアンカー等）はファイル切替は行うが、スクロールはせず通知で挙動を
  明示する
- **中ボタンクリックも左クリックと同じ経路に通す**。片方だけ扱うと既定の新規ウィンドウ要求に落ち、
  外部送りの allowlist を迂回する
- **control+click はリンク起動として扱わず既定挙動に渡す**。macOS では control+click が左クリックと
  して届くため、除外しないと右クリックの意図で外部送りが走る。それ以外の修飾子付きクリックは
  通常クリックと同じ経路（preview にタブやウィンドウのモデルが無く、別挙動を与える意味がない）
- 通知は href ごとに別メッセージを出さず、固定のメッセージと詳細に分けて重複抑制を効かせる

### 内部リンクの履歴

markdown 内の内部リンククリックは back / forward の履歴に積む。ブラウザと同じモデルで双方向の
スタックを保持する。

- リンククリック時: 現在の選択を back に積み、forward を破棄する
- back / forward は「スタックの pop」と「現在の選択を反対側に push」を **1 つの不変条件として実行する**
- **同じパスかつ同じ行番号への再遷移は積まない**
- ヘッダに back / forward ボタンを常時描画する。**履歴の有無でヘッダの幅が揺れないよう、操作不能側は
  disabled で表現する**
- キーバインドは preview が開いていて入力欄にフォーカスが無いときだけ発火する

履歴のスコープ:

- 積まれるのは **markdown のリンククリック由来の遷移のみ**
- それ以外の経路で選択が変化した瞬間に両スタックを破棄する

**履歴スタックの上限は設けない**。人間がリンクをクリックする経路でしか発生しないため。
**本契約を変更する場合は本ファイルを SSOT として書き換え、実装側に隠れた上限を入れない**。

## HTML ビュー

previewed HTML を **実 URL の load** としてネイティブ描画する。

- **文字列の埋め込みを使わない理由**: 文字列を流し込むと文書の base URL が親のものになり、
  previewed HTML の相対リンク・画像・CSS が原理的に解決しない。origin も opaque になり、リンク
  クリックを傍受する経路も無くなる。実 URL なら普通の HTTP と同じ理屈で全部成立する
- **信頼境界**: previewed HTML はリポジトリ内の任意ファイルで untrusted。実 origin を与える代わりに
  **能力を配信時に落とす**。script は動かず、外部への参照もできず、origin が異なるため親の RPC には
  到達しない
- **preview ごとの隔離**: origin は preview ごとに分かれ、配信範囲もその preview に紐づく。
  origin を共有すると隔離が壁にならず、ある preview の HTML から別の preview の配信範囲を参照できる
  （複数 repo の同居は機能要件なので、信頼境界の違うコンテンツが同時に開かれるのが常態）
- **配信範囲**: preview が要求した root 配下だけ。範囲外は配信しない。root は worktree 内なら
  worktree root、worktree 外の絶対パスならそのファイルが居るディレクトリに絞る
- **配信許可の寿命**: 許可は preview に紐づき、preview が消えるときに手放す。同じ preview が別の
  root を要求したら前の root は置き換わる。**取得と解放は直列化し、進行中の要求が解放の後に完了して
  許可を復活させないようにする**
- **表示できる参照**: 配信は作業ツリーの実ファイルを読むため、**表示中の参照がディスクの実体と
  一致するときだけ**ネイティブ描画する。過去版や実体なしではソース表示に倒す。markdown は内容を
  渡して描画するのでこの制限を受けず、**同じ commit を選んでも描画が効く点が観測可能な差になる**
- **更新の反映**: 内容が変わったら表示に反映する。反映は参照している CSS / 画像にも及ぶ
  （URL が変わらなくても古い内容は残らない）。**契機は表示中の内容の変化だけ**で、選択や status の
  更新では再描画しない。並列エージェントが常時ファイルを書き換える前提のため、無関係な変更で
  遷移先やスクロール位置が入口に戻らないようにする
- **popup を封じる**: 中クリックや別ウィンドウ要求はブラウザにブロックさせる。この frame は
  クリックを傍受できる層が無いため、popup 経路が生えると外部送りの allowlist を迂回する
- **リンク遷移**: 配信範囲内は preview 内のページ移動、外部 URL は OS のブラウザで開く
- **外側のポインタ操作を奪わない**: 外側でポインタが押されている間、この面は入力を受け取らない。
  受け取ると、この面を横切ったドラッグが追従を失い、ポインタを離しても操作が終わらない。
  ドラッグに限らず押下中は受け取らないため、押している間この面の hover は止まる
- **背景は白に固定する**。ここで描画するのは gozd の themed UI ではなく白背景前提で書かれた外部
  文書のため、テーマ由来の色ではなくリテラルの白が意味的に正しい

## 変更のまとめ表示

変更一覧の「まとめて表示」で preview を「全変更ファイルの差分を縦に並べるモード」へ切り替える。

### スコープと追従

- **表示する一覧は変更一覧パネルと同じ SSOT を共有する**。uncommitted / 単一コミット / 範囲選択 /
  PR 差分のいずれの選択状態にも追従し、両者は常に同じファイル集合を見る
- worktree を切り替えるとまとめ表示は自動で解除される

### PR 差分モード

PR 差分トグルが ON のとき、各 view は **「merge-base から作業ツリーまで」** の差分に切り替わる。
**base を直接起点にすると、PR 分岐後に base が前進した分が逆向きに混入する**ため、必ず merge-base を
取り直してから使う。

- 一覧は merge-base 起点の差分に untracked を merge した形になる
- ファイル単位の差分は merge-base 側と作業ツリーを並列取得して描画する
- **PR 差分に含まれないファイルを選んだケースは作業ツリーの中身を Current に出して救済する**。
  空表示に倒すと、ツリーで見えているファイルが PR モード中だけ読めなくなる非対称が生じる
- ただし **一覧の取得が未確定な状態を救済に倒さない**。トグル直後は一覧が空で、差分内のファイルも
  一時的に消える。これを救済すると既定タブが Diff から Current へ落ちる。**取得中は救済せず、
  一覧確定による再発火に委ねる**
- 起点の解決は「base 端に到達可能か判定 → 必要なら fetch → merge-base を解決」の順で行い、解決した
  merge-base を固定して以降の基準にする。**有効化時と ON 中の再解決は同じ手順を通る**
- **グラフの選択は触らない**。ユーザーがグラフで commit を選んだら自動で OFF になる
- PR が見つからない / base が未解決のときはトグル自体を無効にする
- base が local に無いときは 1 回だけ自動 fetch する。**ON 中の再解決でも走る**ため、操作していない
  あいだにネットワーク I/O が起きる。その失敗通知は間引く。有効化時の解決失敗は通知して有効化を
  キャンセルする

#### base 端の選択

PR が stack（連鎖する PR の列）に属するとき、意味のある base 端は 2 つある。**選択で変わるのは
base 端だけ**で、差分の右端（作業ツリー）・untracked の扱い・解決手順・自動 OFF の条件は共通にする。

| base 端       | 差分の範囲                                                                  |
| ------------- | --------------------------------------------------------------------------- |
| PR の base    | その PR 単体の変更（GitHub の Files changed と同じ範囲）                    |
| stack の base | stack の下段を含む累積変更（GitHub が stack として merge するのと同じ範囲） |

- **2 つの base 端が同時に有効になることはない**。差分の起点は常に 1 つ
- stack に属さない PR では stack 側のトグルを出さない
- 自動 OFF は **起点が動いたときだけ**。base 端や HEAD が動いても起点（merge-base）が同じなら表示を
  維持する。入力の変化で OFF にすると、起点を動かさない操作（通常の commit、自分が取り込まない base の
  前進）でも落ちる
- **HEAD の追従は commit グラフの表示状態に依存させない**。グラフを開いていない / ロードに失敗している
  間も HEAD の移動を観測できる経路を使う
- stack の下段が merge されたときに OFF になるかは **merge の方式で決まる**。merge commit なら下段の
  変更が自分の履歴の祖先に入るため起点が前進して OFF、squash / rebase merge なら生成された commit は
  祖先にならないため起点は動かず表示を維持する。base 端が動いたかではなく起点が動いたかで決まる、と
  いう上の規則の帰結

### UI 構成

- 1 ファイル = 1 ブロック。ヘッダ（アイコン / パス / 変更種別 / 折りたたみ）と差分本体の組み合わせ
- **表示モードと折り返しはビュー全体で 1 つのツールバーに統合し、ファイル個別のトグルは出さない**

### モード遷移

- ファイル行をクリックするとまとめ表示は解除され、単一ファイル表示に戻る
- **グラフ上で commit / 範囲を切り替えてもまとめ表示は維持される**（スコープに従って集合が
  入れ替わる）
- 解除は close に集約される（上述の不変条件）
- **まとめ表示の有効化と preview の open はペアで遷移する**

### データ取得とリアクティブ更新

- 各ファイルの差分は単一ファイルと同じ取得経路に従う。差分はファイルごとに個別取得する
- **大量変更でも初期描画を固めないため、ビューポートに入って初めて取得する**
- uncommitted モードでは単一ファイルと同じ更新規律に従う。コミットモードではファイル変更を無視する

### 失敗時の通知

- 個別ファイルの失敗はブロック内に表示する
- **並列取得の同時失敗に備え、失敗を集約してトースト 1 件にまとめる**。詳細な件数と直近の原因は
  通知センター側で展開する

## 編集

編集可能なファイルは **常時編集状態**で表示する（明示的な編集モードや Edit ボタンは存在しない）。
編集面は Current タブと Diff タブ（比較元は読み取り専用、比較先が編集可）。

対象は作業ツリーの実ファイルと worktree 外の絶対パスの実ファイル。**Original タブと過去版の表示は
読み取り専用**で、そこでの差分表示は blame と hunk 展開つきの read-only になる。

**読み取り専用の判定は worktree 相対パスにのみ適用する**。絶対パスは git の文脈を持たず常に実体の
表示なので、グラフでコミットを選んでいても編集を塞がない。

編集セッションは単一の状態に集約し、編集可能な内容が表示されると自動で張る。**Current タブと
Diff タブは同じ draft を共有する**ため、片方の未保存編集はもう片方にも反映される。
**保存は明示的で自動保存はしない**。

**保護境界は編集モードのフラグではなく「未保存変更の有無」**。外部変更や対象切替でない再取得は
未保存の間だけ抑止し、クリーンなら追従してセッションを新しい内容で張り替える。

### draft の生存境界

draft の生存は **preview が表示されている間だけ**。不変条件は
「セッションが存在 ⇔ preview 表示中 && まとめ表示外 && 編集可能な内容を表示中」で、**両方向を
別の場所が担う**。

- 畳む側: close（**不可視の未保存 draft を残すと、dirty 表示のないまま外部変更同期で無警告破棄
  される経路が生まれる**）とまとめ表示への進入
- 張る側: 可視状態を含めた同期観測（再 open やまとめ表示からの離脱は内容が変化しないため、
  可視状態自体を発火源にしないと張り直せない）

**破棄が起きる操作は未保存なら確認を挟む**（Save / Don't Save / Cancel）。
**Save がクリーン化に失敗したら操作を中止する**。

| 境界                                                          | 確認     |
| ------------------------------------------------------------- | -------- |
| preview の close 操作、別ファイルへの切替、まとめ表示への進入 | 挟む     |
| 切り離したウィンドウの close                                  | 挟む     |
| worktree 切替、コミット選択の変化 / PR 差分トグル、アプリ終了 | 挟まない |

**確認を挟まない経路では、未保存の編集は通知なく失われる**。これらは preview 単体の操作ではなく
作業対象そのものの切り替えで、確認を挟むと切替がブロックされる。発生頻度が低いため許容する。

**切り離しは破棄ではなく draft の移動**。未保存編集の所有者は常に 1 か所に保たれ、確認なしで
切り離せる。

編集中も blame は使える。差分タブでは左右両側から起動でき、読み取り専用と同じ側の契約に従う。
unified 表示の編集中は比較元の面が隠れるため、比較元側の blame は split でのみ使える。
**blame の対象は保存済みの作業ツリーであり、未保存の draft で行がずれていると blame 行と表示行が
一致しないことがある**。

UI は **未保存の変更があるときだけ** Discard / Save をフローティング表示する。ESC は編集系の意味を
持たず close に一本化する（未保存なら close 前に確認を挟む）。
